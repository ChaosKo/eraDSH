## 修复与防护

- **inplace 构建为游戏的 `Sav` 留快照**：位置 `~/.dsh/era-bridge/sav-snapshots/<游戏名>-<路径哈希>/sav`，按「文件数 + 总字节 + 最新写入时间」判定是否需要重拍，内容没变就复用。构建结果新增 `savBackupPath` / `savBackupFiles` / `savBackupBytes` / `savBackupReused`。脚本侧可用 `-RefreshSavBackup` 强制重拍、`-NoSavBackup` 关闭。
- `copy` 模式本来就不复制 `Sav/Debug/Dat`，因此不加快照。

## 起因（实录）

一次开发期的临时 spike 脚本把真实 `Sav` 移到 `%TEMP%` 后，宿主的 shell 在运行中被中断，`finally` 的还原没有执行；下一个测试脚本启动时又把这个备份目录整体删掉，原始存档因此丢失。事后核对：`Sav` 目录创建时间 = 中断后下一次运行的时刻，与脚本行为一致。插件的正常路径与此无关——`Build-Bridge.ps1` 的 copy 模式显式跳过 `Sav`，宿主 C# 里没有任何 `File.Delete`，eraOCG2 的 ERB 里也没有 `DELETEFILE`。

## 使用提示

- 快照只是"上一次内容"的副本，不是版本历史；需要多份就自己复制目录。
- 快照会随游戏进度变化而在下一次构建时刷新，因此长时间不构建时它停留在旧状态。
