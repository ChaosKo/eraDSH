## 新增

- **`era-bridge` 与 `era-dev` 技能**：随插件分发，由 Host 插件通过技能注册表注册，因此标准模式、Era 模式与任何自建预设都能在目录里看到，按需加载正文。`era-bridge` 是玩法与工具手册（七个动作、观察与动作规则、省上下文、Era 游戏基础、自主游玩、信任边界），`era-dev` 是本仓库的开发手册（结构、开发循环、测试清单、发布约定、边界）。
- **Era 开发模式预设（`era-dev`）**：从随 DSH 发行的 `standard` 预设派生——同一份插件清单，另加面向本仓库的开发 persona。用来改插件代码、构建桥接、跑回归测试，同时能直接调用 `era_bridge` 做端到端验证。

## 澄清：工具本来就在标准模式里

`era_bridge` 由 Host 级的 `dsh-era-bridge` 行注册，工具注册表把全局注册合并进每个 Agent 视角，所以标准模式一直可以调用它（本次核对方式：在标准模式会话里用 Cordis `Tool.listTools` inspect，`era_bridge` 在列表中）。这次补的是**知识**而不是工具：此前玩法手册只写在 Era 模式的 persona 里，标准模式拿到的是裸工具、没有用法说明，也没有任何预设覆盖「开发这个插件本身」的路线。

## 设计取舍

- **为什么不直接改 `preset-standard`**：Loader 的 patch 语义是 `config` 整块替换、不深合并，覆盖标准预设意味着把此刻的插件清单钉死在这个仓库里，DSH 升级后标准模式会倒退。派生新预设不动标准模式。
- **为什么预设里不挂 `dsh-era-bridge`**：工具与技能已经是 Host 级注册，按预设再挂一份只会在该预设作用域里遮蔽同一份定义。
- **派生预设的维护成本**：`preset-era-dev` 的插件清单是 `@deepseek-ai/dsh-web-app` 里 `presets/standard.patch.yml` 的副本。DSH 更新标准预设后需要重新同步这份清单，否则开发模式会落后于标准模式。

## 验证

- `node --check index.js` 通过；`dsh --profile web --dump-config` 能组合出 `preset-era-dev`，23 个子插件与标准预设逐条一致。
- `plugin_manager` 的 `set_bundle` 重新应用 bundle 后：`list_plugins` 出现 `include:preset-era-dev`（`enabled: true`、`fiberPhase: active`），bundle 行数从 249 变 250。
- 同一个标准模式会话的技能目录当场出现了 `era-bridge` 与 `era-dev` 两项——这条同时证明了 Host 级技能注册对标准模式生效。

## 升级提示

- 修改 bundle patch 后需要重新应用一次 bundle（Web UI 插件管理里重装/重新启用，或重启 `dsh web`），预设才会进入 roster。已存在的会话保持自己的预设修订，新预设要在新会话里验证。
